# Spec Delta

## ADDED Requirements

### Requirement: 复习队列不设每日题量上限

系统 SHALL 把全部已到期题与全部从未排期的题纳入记忆复习队列，MUST NOT 施加每日题量上限、分批归还，或把任何已到期题推迟到以后。队列长度只由排期决定，不受当天题量、逾期规模或用户历史行为影响。

#### Scenario: 长时间停练后全量入队

- **WHEN** 用户停练满 7 天后进入记忆模式（此时全库排期均已到期）
- **THEN** 队列包含全部题目，条数等于题库总数，不出现「只给一部分」

#### Scenario: 逾期规模再大也不裁剪

- **WHEN** 队列中逾期题的规模超过任何单日可完成的量
- **THEN** 系统仍然全部入队，MUST NOT 静默丢弃、推迟或按天分配

#### Scenario: 新题不设每日限额

- **WHEN** 题库中存在从未评过分的题
- **THEN** 这些题全部进入队列，不因「每日新题数」被挡在外面

### Requirement: 长期欠账不使用告警语气

当队列最久逾期天数超过排期上限时，系统 SHALL 以中性语气呈现该欠账提示，MUST NOT 使用「出错/危险」级别的告警色。系统 MUST NOT 为解释欠账而插入需要用户先确认才能继续的整屏说明，也不得因任何解释性界面而改变队列的内容、数量或是否入队的判定。

#### Scenario: 停练半个月后的提示语气

- **WHEN** 队列最久逾期天数超过排期上限
- **THEN** 该提示用中性色而非告警色，措辞不带有罪化暗示

#### Scenario: 不插入打断式说明屏

- **WHEN** 用户长期未复习后进入记忆模式
- **THEN** 直接开始复习，不出现需要点一下才能继续的整屏说明

#### Scenario: 队列不因解释而变短

- **WHEN** 界面呈现欠账相关的信息
- **THEN** 队列条数与该信息呈现之前完全相同

### Requirement: 可提取性对用户可见

系统 SHALL 在复习界面与进度报表中展示每道题当前的可提取性 R（此刻能成功回忆的估计概率），取值口径 MUST 与调度内部使用的那一个一致：按真实经过时间计算，老记录经同一套换算得到稳定度。对没有任何记忆状态的题，系统 MUST 显示为「无数据」，不得显示 0% 或 100%。

#### Scenario: 已评分题显示 R

- **WHEN** 一道题曾被评过分并有记忆状态
- **THEN** 复习卡头部与进度报表都给出其当前 R

#### Scenario: 老数据同样有 R

- **WHEN** 一道题只有旧版排期字段、没有新版记忆状态
- **THEN** 系统按与进度页稳定性/难度相同的换算路径得出 R，不显示为「无数据」

#### Scenario: 从未学过的题不谎报

- **WHEN** 一道题从未被翻看也从未被评分
- **THEN** R 显示为「无数据」占位，而不是 0% 或 100%

#### Scenario: 逾期越久 R 越低

- **WHEN** 同一道题在更长的未复习间隔后被查看
- **THEN** 显示的 R 随经过时间单调下降，且与到期与否的判定不矛盾

### Requirement: 复习顺序按可靠性从低到高

系统 SHALL 先把从未评过分的题排在队列最前，其后再按可提取性 R 从低到高排序，使最不可靠的题最先出现。排序结果 MUST 稳定：同一份数据在相同时刻重复构建队列应得到相同顺序。

#### Scenario: 新题优先

- **WHEN** 队列中同时存在未评过分的题与已评过分的题
- **THEN** 未评过分的题排在前面

#### Scenario: 已评题中最不可靠的先出现

- **WHEN** 队列中存在 R 高与 R 低的已评题
- **THEN** R 低的题排在 R 高的题之前

#### Scenario: 顺序可复现

- **WHEN** 数据未变化而队列被重复构建
- **THEN** 两次得到的题目顺序一致，不因渲染时机而抖动
