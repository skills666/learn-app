# Proposal

## Why

停练半个月回到应用，界面上只剩「待复习 1000」和一行红字「⚠ 队列最久欠 15 天」。因为排期间隔被封顶在 7 天，停练满一周后**全库同时到期**，「到期 / 没到期」这个二值信号就此失去区分度：用户看不出哪些题真的凉了、哪些其实还很稳，也看不出这一摞牌到底有多厚。

而答案本来就在调度器里——可提取性 R（`fsrsRetrievability`，d:\learn\learn-app\index.html L2223）已经实现，却只在调度内部被调用两次（L2250、L2255），界面从没露出过一次。稳定性 S 与难度 D 早已在进度页显示，DSR 三件套只缺最后一个。这是纯展示缺口，不是能力缺口。

## What Changes

- **暴露可提取性 R**：新增共享口径函数 `retrievabilityOf(p, now)`，与 `effectiveNextOf` 并排（L2307 附近）；在记忆卡头部与进度页数据行显示 R。无任何记忆状态的题显示 `—`，不得显示 0% 或 100%（前者谎报已忘，后者谎报已会）。
- **复习顺序改为「最不可靠的先来」**：`buildMemoryQueue` 的排序（L4639）第二优先级由 `overdue` 降序改为 R 升序；`isNew`（从未评过分的新题）仍保持第一优先级。
- **欠账构成可见**（已移除，见下方「修订」）
- ~~**千题规模下的进度可见**：把「3/1000」这类无意义的分数改为分段进度条~~（已移除，见下方「修订」）

**修订（用户实测后砍掉的两项）**：上面的「欠账三段计数」与「回归说明整屏」已在真实数据（停练 16 天 / 253 题）上被判定无价值，本 change 不再包含它们：

- 欠账分段计数对行动零指示力 —— 「先刷哪个」这个决策已经由 R 升序排序做完了，三段只是在解释系统怎么想的。`queue.seg` 的两个消费者都消失后，该派生量一并删除，不留死代码。
- 回归说明屏四行里只有一句有信息量（停了多少天、多少题到期），而这句话卡片头部的「🕒 队列最久欠 N 天」已经给了。整屏打断式说明与 `learnAppBrief_v1` 标记键一并移除。
- 总览卡上的等式文字（「记忆队列 N 题 = 到期 X + 未学 Y」）同步移除：它冗余，且 `.ov-grid` 是 `repeat(5,1fr)` 的 grid，同行卡片默认等高 —— 单张卡多一行文字会把整排（包括保留率卡）顶高。**但「到期 / 未学」两个数字同权重并排保留**，那才是最初误读的解药。
- **20 格分段进度条也已整体移除**（用户实测后指出）：它跟既有的一直存在的「等级分布条」`.pbar.lvbar` 形状相同、语义完全不同，且两条横带上下相邻，被当成"没删干净的残留"。这是本次改动造成的真实视觉冗余：当前规模（百题级）下 `11/40` 这个分数已经足够，分段条要解决的「千题规模读不出还剩多少」并不成立。`MEM_PROG_SEGS` / `memProgIdx` / `buildMemProgHtml` / `paintMemProg` / `.mem-prog` 及其 CSS 全部删除。

**明确不做（本次的硬边界）**：不设每日题量上限，不裁剪队列，不分批归还，不把任何到期题推到明天。凡到期即入队，排期来了多少题就刷多少，再多题也进队列。也不做打断式的回归说明屏。本次所有改动只影响「怎么说、按什么顺序排」，不影响「进不进队列」。

**不改的**：FSRS 权重与四档→间隔的映射、`FSRS_MAX_INTERVAL` / `FSRS_RETENTION` / `MASTERED_MIN_DAYS` 三个参数、跳过（memory-skip）与趁热打铁的零副作用语义、评分按钮上已有的间隔预览（`fsrsPreview`，L5172-5180 已显示「半天后 / N 天后」）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `memory-scheduling`：新增四条契约——① 队列完整性（不设每日上限，到期即全量入队；任何解释性界面都不得让队列变短）；② 调度导出量的可观察性（可提取性 R 必须对用户可见，且与调度内部同一套取值口径）；③ 复习顺序规则（新题优先，其后按 R 升序）；④ 长期欠账用中性语气，不用告警色。

把 ① 写成契约的理由：这是一个只能靠规格守住的决策。没有它，将来任何一次「优化复习负担」的提案都会自然地把每日上限当成解法，而它恰好与「面试随时可能发生」这条既有契约冲突——两者必须留下一条谁赢的记录。

## Impact

- **代码**：唯一源 d:\learn\learn-app\index.html 内四处——新增 `retrievabilityOf`（L2307 旁）、`buildMemoryQueue`（排序改用 R）、记忆卡头部 pmeta（L5144-5149）、进度页数据行（L5195-5227，rows 已有 `s`/`d`，加 `r`）+ 总览待复习卡。另加分段进度条的 CSS。
- **口径约束**：R 的 `elapsed` 走真实毫秒差（与调度内部 L2247 一致），**不采用** `dayIndexOf` 的自然日口径（后者只服务「欠几天」的整数语义）。若两处混用，会出现「进度页说 R=88%、记忆页说还没到期」的自相矛盾。
- **持久化（已取消）**：原先计划新增一个「回归态已展示」标记键，该特性已移除，本 change 不再新增任何持久化键。
- **测试**：d:\learn\learn-app\scripts\smoke-test.js 需补 R 计算与队列排序的行为断言，并删掉已取消特性的断言（欠账三段、回归说明）；注意沙箱约束——常量要单独成行声明才能被 `extractConst` 取出（L139-145），函数不能依赖未声明的外部标识符否则 `extractFunction` 沙箱直接 ReferenceError（L7887-7888 是这个坑的既往记录）。d:\learn\learn-app\scripts\render-smoke.js 同理：保留队列不裁剪与分段条的断言，移除说明态断言。
- **版本号双写**：改完必须同步递增 `index.html` 的 `SW_VERSION` 与 `sw.js` 的 `CACHE`，否则 `sync-www.js` 拒绝打包。
- **不受影响**：任何排期数值、PROGRESS 字段结构、云同步载荷、Android 原生层、文档页与刷题模式。
