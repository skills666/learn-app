# Design

## Context

动机见 proposal.md - Why。这里只列约束做法的现状：

- 打卡类数据已经是「按日累计、只增」的形状：WARLOG 以本地自然日键分层，每台设备一个桶（`WARLOG[dayKey][devId] = {c[4], q[], nw, mUp, mDown, up, down, at}`，L2588-2613），跨设备读取走 `warDayAgg` 汇总（L2515-2524）。**不需要新造数据结构**，缺的只是"让它活得更久"和"热力图改读它"。
- 现有裁剪 `warLogTrim`（L2527-2531）按 `WARLOG_KEEP = 45`（L2443）直接 `delete` 超期日键。这个 45 同时服务于三件事：每日战报只看昨天与前天、明细气泡给四档构成、色阶不受影响（色阶当前根本不读 WARLOG）。**一个常量担了两个语义**，这正是本次要拆开的东西。
- `q` 数组唯一的读取方是 `warDayAgg` 的跨设备去重（L2518-2519），产物是 `out.uniq = out.q.length`（L2523，注释「覆盖题数 = 跨设备去重后的题号数」）。热力图当前不读它。
- 日期口径在本项目里有两套且刻意分开：`dayKeyOf(ts)` 产出本地自然日字符串键（L2452），`hmDayNo` / `hmCivil` 产出格子用的 UTC 日序号（L5286-5287）；跨天回推有现成的日历减法 `warPrevKey(key, back)`（L2650，注释专门说明为什么不能用减毫秒——夏令时那两天不是整 24 小时）。
- 落盘模式已有两套并存：进度走 600ms 防抖 + 强制 flush（`_progWriteTimer`，L4046-4050；`pagehide` 与 `visibilitychange` 都挂），而 `warLogAdd` 是**每次评分同步 `JSON.stringify` 整份写**（L2603）。Android 退出路径（L2243 附近、`backButton` 处理器 L3240-3243）当初专门补了显式 flush，注释写明「不能指望 pagehide / visibilitychange 一定派发」。
- 色阶阈值 `hmLvOf(n)` = 0 / 1-2 / 3-5 / 6-10 / 11+（L5301），入参 n 的语义是「题数」。

## Goals / Non-Goals

**Goals:**

- 打卡事实变成只增，热力图与连续天数从此只依赖它。
- 在存储与同步载荷可接受的条件下把打卡保留到够覆盖年度视图。
- 不新增数据结构、不新增日志文件、不新增第三方依赖。

**Non-Goals:**

- 不恢复已丢失的历史（做不到，见 proposal）。
- 不重标定色阶阈值（`hmLvOf` 原样沿用）。
- 不跨年保留与显示：视图已经是「今年 1/1~12/31」单年视图（L5284 注释），**本次不动它**，只把打卡保留期钉到够覆盖当年。
- 不为老日期保留逐题清单（`q` 数组），但**也不收窄回看能力**：当年内有记录的日子照旧可点开看明细与战报入口。
- 不改 `q` 数组在近 45 天内的任何行为，也不改战报数字口径。

## Decisions

### D1：复用 WARLOG，不新开第三份打卡日志

打卡事实就是「那天有几个设备记录、覆盖了几道题」，WARLOG 已经按这个形状存在并且已经做好了跨设备分层合并（`at` 做新旧标记、逐设备取新）。再开一份专用打卡日志会把同一件事存第三遍（项目里已有 WARLOG 与 REVLOG 两份只增日志），与「同一件事只在一处」这条贯穿全文件的自述原则冲突。

- **替代方案（已否）**：新建 `learnAppCheckIn` 独立存储。多一处落盘、多一处云同步、多一套合并语义，收益只有"语义更直白"。
- **代价**：WARLOG 的保留期与载荷被打卡需求拉长，云同步里 `warlog-data.json` 每次推送都整包带上。用 D3 的折叠把代价压到几十 KB 量级。

### D2：一个常量拆成两个

```
WARLOG_QID_KEEP = 45      // 逐题清单保留期：决定那天是否还能精确去重算出覆盖题数
WARLOG_CHECKIN_KEEP = 370  // 打卡保留期：决定颜色与回看能活多久（覆盖当前年最长 366 天）
```

370 = 年度视图最长 366 天（闰年 1/1~12/31）+ 几天余量，避免跨年边界、日界与跨零点评分把年内已打卡的日子裁掉。跨年自然翻篇：视图只看今年，去年的键在超出 370 天后清掉。

- **为什么不写成 365 整**：`dayKeyOf` 用本地日界，而打卡桶按设备各自的时间戳归档，跨时区设备合并时会出现同一 UTC 日不同本地日的边界情况；余量比"精确"更划算。
- **保留旧名 `WARLOG_KEEP` 作为别名？不**。两个语义混在一个名字上正是本次的病因，直接改名并让编译器/门禁（`extractConst`）逐条取出。

### D3：折叠 = 丢 `q`，留计数

超出明细保留期时，把桶就地折叠为 `{ c[4], qn, nw, mUp, mDown, up, down, at }`，其中 `qn = q.length` 在折叠那一刻写死，随后删除 `q` 数组。

- **为什么连 `c`/`nw`/`up` 这些也留着**：都是几个数字，成本可忽略；将来若要画"长周期的档位趋势"不必再动数据结构。**唯一必须删的是 `q`**，它是全年成本的来源（一天几十到几百个 qid 字符串）。
- **色阶读哪个数**：读题数（近 45 天用 `q.length`，更早用 `qn`），不读评分次数 `total`。理由：`hmLvOf` 的阈值语义就是题数，改成次数会让"同一天反复刷同一题"把颜色刷深，与打卡墙的直觉不符，还要重新标定阈值。这是选择不重标定的根据。
- **`warDayAgg` 的 `uniq` 加回退**：有 `q` 用去重后的 `q` 长度，没有则累加各设备 `qn`。**这一步不是可选项**：老日子仍然可点（R4），没有回退就会显示「复习 0 题」而把明细变成可点但全空。
- **`qn` 相加是跨设备的上界**，无法再精确去重（两台设备当天练了同一道题会算两遍）。因为回看不收窄，这个数**会外显**，所以明细文案对已无 `q` 的日子用「复习约 N 题」，对仍有 `q` 的日子保持「复习 N 题」——用一个字的差别说清它是估计值，不假装精确。判定条件就是「该天是否还有 `q`」，不需要新状态。

### D4：色阶与连续天数的取数路径

```
hmDayCounts()  -->  遍历打卡记录的日键（全部设备桶），
                     题量 = 近期 q 去重数 / 超期 qn 之和
                     Map<dayNo, 题量> 的对外形状与只读约定不变（缓存仍归 invalidateMemQueue 作废）

streak         -->  有打卡的日期集合（本地日键）
                     从今天起用 warPrevKey(todayKey, i) 逐日回推，命中则计数
```

- **为什么 streak 用 `warPrevKey` 而不是格子日序号**：项目里已经有刻意写对的日历减法（L2650，夏令时那天的坑）。用它就不引入第三套日期算术，也避免把 `hmDayNo`（UTC 日序号）和 `dayKeyOf`（本地日键）混在同一个循环里比较。
- **`computeAllStats` 的 `reviewed` 集合**从 `lastPracticed` 建（L3354-3356）改为从打卡日键建；`todayDone`（今日已刷题数）保持读 `lastPracticed` 不动——它的语义确实是"今天推进过几题"，与打卡墙不是同一个问题，不要顺手一起改。

### D5：撤销不回退打卡（我的判断，非你指定）

`warLogUndo` 继续回退四档计数与 `nw`/`mUp`/`up` 等数字，但**不删日桶、不减 `qn`**。因此撤销不会让那天变暗。

- **依据**：L2616 已经就 `q` 做过同一个决定——「覆盖题数 `d.q` 不回收：日志里没有逐题次数可依据，宁可多算一道覆盖也不漏」。撤销一次评分改变的是"那天的成绩"，不是"那天有没有学"。
- 这一条需要在代码注释与 specs 场景里都锁住，否则将来有人"顺手把撤销做成完全对称"就会让打卡墙重新变得可回退。

### D6：落盘防抖必须三处 flush 齐全

给 WARLOG 加 600ms 合并写（沿用 `_progWriteTimer` 的写法），并**同时**把战报落盘补进三个既有出口：`pagehide`（L4050）、`visibilitychange` 隐藏分支（L4052）、Android `backButton` 退出路径（L3243 那行 `flushProgressWrite(); saveGrillDraft(true);` 旁边）。

- **为什么这是硬性而不是优化**：当年正是"进度有防抖、退出时刻落在窗口内、最后一次评分只在内存里"才补的显式 flush（L3240-3242 注释写着不能指望 pagehide/visibilitychange 一定派发）。**只加防抖不补 flush，就是亲手复现一个已经修过的 bug**，而且丢的是打卡——正是本 change 要保住的东西。
- 不做"每 N 题才写一次"这种批量阈值方案：崩溃时丢一批打卡，与目标相反。

### D7：文字与注释的连带修正

- L5281-5283 那段「现有数据完全够用」的论证改写为按日累计的真实口径说明（说明为什么不能用会被覆盖的字段）。
- L3375 那条「上限 3650 是为了不让满年用户恒定显示 365」补一句：真正的钳制曾经来自数据源，现在来自打卡保留期。
- 色阶图例（`hmScaleHtml`，L5302）旁补一行「颜色 = 那天练过的题数」，避免用户把颜色理解成"记得率"。

## 只读盘点结论（tasks 1.1–1.3）

- **`q` 与 `uniq` 的读取方只有一处**：`warDayAgg`（d:\learn\learn-app\index.html 的 `warDayAgg`）。它产出的 `uniq` 被 `buildWarReport`（战报模态里的「覆盖 N 道题」）和 `warQuip` 读；`q` 数组本身没有任何第二个读取方。所以折叠掉 `q` 不会砸到清单外的路径。
- **`markPracticed`（刷题模式翻页）只写 `practiced` / `lastPracticed`，不写 WARLOG**。所以换源后「只翻页未评分」自然不算打卡（与 R2 一致），而 `todayDone`（今日已刷）仍按 `lastPracticed` 计 —— 两个问题不混用。
- **两条清除路径都不动 WARLOG**：`resetBtn`（仅清除进度）只清 `PROGRESS`；`clearAllDocs`（清空全部文档和学习数据）清 `DOCS/PROGRESS/CLEARS/ORDER`。所以清进度后打卡墙与连续天数仍保留（已写成断言）。
- **未决**：`clearAllDocs` 的按钮文案是「清空全部文档和学习数据」，但它不清战报/打卡 —— 文案与实际不符。本 change 不擅改（那属于新的行为变更）：要么在它里一并清 WARLOG/REVLOG，要么改文案。

## Risks / Trade-offs

- **[已经熄灭的日子救不回来]** 事实如此，不缓解。proposal 已写明，用户第一次看到"今年还是有大片空白"时不应感到被背叛——建议在实现完成后于 changelog/文案里也提一次。
- **[打卡定义变窄]** 换源后"只翻页没评分"不再算打卡（specs 里 R2 明写了这条）。这是刻意的诚实选择，但会让他短期内觉得图比现在更空。**开关**：若要浏览也算打卡，让 `markPracticed` 给当天桶加一个 `v` 计数（不进 `q`、不进 `c`、不影响战报任何数字），色阶读 `qn + v` 即可，一行成本。默认不做，先用一个周期观察他是否真的在意。
- **[防抖丢数据]** → D6 的三处 flush 是必须项，不是可选项；补一条断言：退出前未 flush 的最后一笔归档不丢。
- **[qn 跨设备重复计数会外显]** 因为老日子照旧可点，这个偏差用户看得到 → **缓解**：对已无 `q` 的日子文案改用「复习约 N 题」，不拿估计值冒充精确值；近 45 天仍是精确去重值。
- **[回滚是单向门]** → 回滚到旧代码后，`warLogTrim` 会按 45 天把新写的老打卡立刻裁掉，等于回到今天的行为。这是可接受的（回到已知状态），但要知道：**回滚不会保留已经画出来的墙**。
- **[云同步载荷线性变大]** → 折叠后估算为几十 KB（经验值，非实测）。若将来撞上配额，第一选择是让超期桶不上云（各设备各画各的墙），代价是跨设备打卡不再合并——那会违反 R1 的第 4 个场景，属于产品决定，需要重新讨论而不是偷偷实现。
- **[改动面广]** `hmDayCounts` 同时被年度视图、月视图、明细气泡共用（L5288 注释），换源后三处一起变；`_hmCountsCache` 的失效仍挂在 `invalidateMemQueue`（L4585）上，缓存"只读"约定不能破。

## Migration Plan

1. 先只读盘点：列出 `q` 与 `uniq` 的全部读取方（当前已知 `warDayAgg` L2518-2523），确认折叠 `q` 不砸到别处。
2. 拆常量（D2）+ 实现折叠（D3），**此步只改裁剪行为，不动任何读取路径**，先让数据形状稳定下来。
3. 加 `uniq` 的 `qn` 回退（D3），断言"折叠日期聚合统计不算 0"。
4. 换色阶与 streak 数据源（D4），并锁住"重刷后老日期不变暗""撤销后不变暗""streak 能超过 7"。
5. 回看保持不变，只把已无逐题清单日子的题量标成「约」（D3 末尾）；确认跨年不显示也不保留。
6. 加防抖并补三处 flush（D6）。
7. 文案与注释修正（D7）。
8. 版本号双写，`npm run verify`。

**回滚**：`git revert`。回滚后打卡退回 45 天口径（见上面的单向门说明），代码行为即回到当前已知状态。

## Open Questions

- 浏览日要不要算打卡（D7 里的 `v` 开关）：默认不算，等一个周期看是否在意；不影响 specs 结构与任务拆分。
- 色阶阈值 `hmLvOf` 在新数据源下是否需要视觉再平衡：默认不动，若全年颜色普遍偏浅再单独调，属于同一函数的一行改动。
