# Design

## Context

见 `proposal.md - Why`（现象与根因）。这里只补充约束渲染改动的**当前状态**：

- 题目答案在刷题页与浏览页都走 `renderAnswer`（`index.html`），流程是：`esc(t)` → 抽代码围栏为占位符 → 行内 `**粗**` / `` `码` `` → 段落/`<br>`。它**不认**列表、标题，也**不还原**反斜杠转义。
- AI 回复走另一条更强的 `md2html`：已支持 `#` 标题、`-`/`1.` 列表，但同样先 `esc`、不还原反斜杠。
- 导入侧 `parseMarkdownToDoc → stripMarkdown` 把答案正文原样存入 `DOCS`（`q.answer` 里保留了 `\`、`-`、`1.` 等源字节）。
- 硬约束（`project.md`）：单文件、零运行时依赖、所有 `innerHTML` 注入点必须先经转义；改 `index.html` 须与 `sw.js` **双写版本号**。

## Goals / Non-Goals

**Goals：**
- 刷题/浏览答案：代码外还原反斜杠转义；`-`/`*`/`+` 与 `1.` 渲染为列表。
- 修复对**已导入旧数据**同样生效（落在渲染期，不需重导 / 迁移）。
- 代码块（围栏 + 行内码）内容逐字不变，包括其中的 `\`、`-`、`1.`。

**Non-Goals：**
- 不引入外部 Markdown 库，不改 `esc` 的转义集与 CSP 底线（不放开任意内联 HTML）。
- 本次不做：正文中间 `---` 分隔线、`>` 引用、表格、列表嵌套缩进的层级还原。
- 不改 `md2html`（AI 回复路径）；如需统一留待后续。

## Decisions

**D1 — 修复落点在渲染期 `renderAnswer`，而非只改导入 `stripMarkdown`。**
渲染期改一次即对全部新旧题目生效，且列表本就是「存储原文 + 渲染期解析」的模式。替代：只改 `stripMarkdown`（导入期剥符号）→ 已入库的旧题仍是坏的、要重导；且 `qid`/tags 由剥离后标题生成会连带变动 → 否决。存储文本保持原样，作为唯一数据源。

**D2 — 反斜杠还原用「先占位、末尾再落地」的方式，且只针对 ASCII 标点。**
流程：`esc(t)` → 抽代码围栏 → 对**围栏外**文本，把 `\X`（`X ∈ \`*_{}[]()#+-.!<>~|"` 及 `` ` ``）替换为「目标字面字符」的占位符 → 之后再跑 `**粗**`/`` `码` `` 解析 → 输出前用占位符回填成**已转义**的字面字符。
- 关键理由：直接 `replace(/\\(.)/g,'$1')` 会把 `\*\*x\*\*` 还原成 `**x**`，随后被加粗正则误解析；先占位可杜绝「还原出的符号再被二次解释」。
- 只吃「`\` + ASCII 标点」，与 CommonMark 一致 → `C:\temp`（`\t`）、`\d`（正则）这类「`\` + 字母/数字」保持原样，避免误删。替代：无差别去 `\` → 误伤 Windows 路径/正则字面量 → 否决。

**D3 — 列表渲染从 `md2html` 移植到 `renderAnswer`，扁平化、跳过代码。**
在段落切分前按行识别 `^([-*+]) +` 与 `^\d+\. +`，聚成 `<ul>/<ol><li>`；复用「代码围栏占位符」机制，行首标记若落在占位符内则不识别。序号仅认 `N.`（点 + 空格）这一标准形式，不额外认 `N)`、`N、`（非标准、易误判正文）。嵌套缩进 v1 不还原层级（与现有 `md2html` 行为一致）。

**D4 — 尖括号仍按字面文本。**
`List<String>`、未被反斜杠包裹的 `<form>` 经 `esc` 显示为字面文本；本变更不放开 HTML 渲染，与 spec「零依赖与转义安全底线」一致。

**D5 — 列表改为行级扫描、跨空行聚合、有序保留起始号（①）。**
上轮按「空行切段」建模，导致 `1.↵↵2.↵↵3.`（松列表，AI/语雀导出常见）被拆成多个单元 `<ol>`、浏览器全显 1.。改成像 `md2html` 那样逐行扫描：相邻列表项（无论是否隔空行）归入同一 `<ul>/<ol>`，有序列表用 `<ol start="N">`（N=首项原序号）；只有遇到非空且非列表行才关闭列表。代价：紧接列表后的一行普通文本需正确断列。

**D6 — 搜索摘要复用同一套「去符号」逻辑（②）。**
`renderSearch` 摘要读的是存库原文 `q.answer`（非渲染期），所以必须单独清洗：抽一个共享的「反斜杠还原 + Markdown 去标记→纯文本」辅助，摘要与答案正文共用同一口径，避免符号只在一处消失。摘要仍保持围绕命中位置截取，不引入块级标签。

**D7 — 导入丢弃「无正文」标题（③，B）。**
`parseMarkdownToDoc` 生成 questions 后，过滤掉 trim 后正文为空的条目（分类名等）。选 B 而非「按 H1 拆文档」：改动小、不触碰「一文件=一文档」与合并/去重逻辑。代价：分类名不保留；若某分类标题与首题之间写了导语，该导语会归到分类标题那道题上（可接受）。

## Risks / Trade-offs

- [还原范围过宽，吃掉正文里合法的 `\`] → 严格限定「`\` + ASCII 标点」白名单，字母/数字/空格后的 `\` 不动；补单测钉死 `C:\temp`、`\d` 不被改。
- [占位符与既有 `\u0001CB` 代码占位符冲突] → 用独立控制字符前缀（如 `\u0001BS<idx>\u0001`），回填顺序放在代码块回填之前/之后需明确、互不覆盖。
- [列表识别误伤普通行，如以 `-` 开头的破折号句] → 只在 `-` 后紧跟空格时判定为列表项；无空格（如 `--`、`-词`）按正文。
- [嵌套/多段列表与段落 `<br>` 交互产生非法嵌套] → 参照现有「代码块独占一段」的处理，列表块整体作为块级输出，不被 `<p>` 包裹。

## Migration Plan

无数据迁移：修复在渲染期，旧题目下次渲染即生效。回滚 = 还原 `renderAnswer`（及若触及的 `stripMarkdown`）+ 版本号双写复位。部署沿用现有 `npm run check` / `npm test` / `sync-www.js` 校验流水线。
