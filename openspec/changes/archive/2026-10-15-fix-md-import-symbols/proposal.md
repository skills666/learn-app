# Proposal

## Why

导入题库（Markdown）后，刷题/浏览页把本该被 Markdown 预览「消化掉」的字符原样显示出来：答案里的 `\<form\>`、`form\-data` 露出多余的反斜杠 `\`；正文开头的 `- 项目`、`1. 步骤` 也显示成裸的 `-` / `1.`，而不是项目符号与序号。

根因不是导入「凭空造符号」——这些 `\` 一直存在于源 `.md` 文件字节里（语雀/Notion/pandoc 等导出工具会自动反斜杠转义），只是正常 Markdown 预览会隐藏它们。而本 App 刷题答案走的是**弱渲染器 `renderAnswer`**：既不还原反斜杠转义，也不支持列表/标题，于是第一次把它们暴露了出来。属于渲染缺项，需要在导入/渲染侧修复，用户无需手工清洗每个文件。

## What Changes

- **还原 Markdown 反斜杠转义**：在**代码块之外**，把 `\X` 还原为 `X`（`X` 为 Markdown 可转义标点：`` \ ` * _ { } [ ] ( ) # + - . ! < > ~ | `` 等），去掉 `\<` `\>` `\-` 这类多余的反斜杠。
- **`renderAnswer` 补齐列表渲染**：无序列表（`-` / `*` / `+` 开头）与有序列表（`1.` 等序号开头）渲染为真正的项目符号 / 编号列表，含常见缩进。
- **代码保护不回退**：代码围栏（```` ``` ````）与行内代码（`` ` ``）内部的 `\`、`-`、`1.` 等**必须原样保留**，不还原、不误当列表；保持现有「代码块降级」相关断言与行为不变。
- **零依赖 / 安全底线不变**：不引入外部 Markdown 库，不放行任意内联 HTML，不改动 `esc` 的 `&<>\"` 转义与 CSP 约束（保持单文件、离线、零运行时依赖）。

### 真实题库 `java.md` 验证后的补充（同属本变更）

- **①（修正上轮列表实现不完整）**：空行分隔的「松列表」也归入同一个 `<ul>/<ol>`，且有序列表按原序号设 `start`，不再每条各成一个从 1 重数的列表（java.md 抢单分布式锁题 617-621 行实跑复现）。
- **②（搜索摘要残留符号）**：搜索结果卡片的答案摘要不走 `renderAnswer`，而是直接截原文 `esc`（index.html 第 6620-6624 行），仍会露出 `\<form\>` 等符号；改为摘要先做反斜杠还原 + Markdown 去标记（纯文本）再显示。
- **③（分类名变空题目）**：`parseMarkdownToDoc` 只在「全文唯一 H1」时才当文档标题；java.md 有 47 个 H1 分类 + 280 个 H2 题目，H1 全被当题目且正文为空 → 空卡片。按 **B 方案**：丢弃「到下一个标题之间无正文」的标题，不为其生成题目。

非目标（本次不做）：正文中间 `---` 分隔线、`>` 引用、表格、内联 HTML 标签渲染；分类的层级/分组归属（B 方案不保留分类名）——留待后续独立变更。

## Capabilities

### New Capabilities

- `markdown-answer-rendering`：定义题库题目（标题与答案）在「导入解析」与「刷题/浏览渲染」两个环节所遵循的 Markdown 子集行为——反斜杠转义还原的范围与代码保护边界、列表渲染（含松列表与有序编号）的可观察结果，以及零依赖/转义安全约束。
- `markdown-import-structure`：定义 Markdown 导入时标题到题目/文档的映射规则——「到下一个标题之间无正文」的标题不生成题目（分类名等空标题被丢弃）。

### Modified Capabilities

（无。既有 `memory-skip` 需求不变。）

## Impact

- **代码**：`index.html` 的 `renderAnswer`、`stripMarkdown`（及其对 `esc` 的调用顺序）；导入链 `parseMarkdownToDoc` 复用 `stripMarkdown`，同步受益。
- **既有数据**：修复落在**渲染期**（`renderAnswer`），已导入的旧题下次渲染即生效，无需重新导入或数据迁移。
- **测试**：`scripts/smoke-test.js` 增加函数级断言（反斜杠还原、代码内不还原、列表渲染）。
- **版本双写**：`index.html` 的 `SW_VERSION` 与 `sw.js` 的 `CACHE` 必须同递增，`sync-www.js` 打包前校验。
- **门禁**：`npm run check` + `npm test`（含 `render-smoke.js` 渲染冒烟）须通过。
