# Design

## Context

动机见 proposal.md - Why。这里只列约束做法的现状：

- `buildForecastHtml(rows, days)`（d:\learn\learn-app\index.html L5454-5492）的入参是 `buildAnalyticsData` 的 rows，而 rows 已经携带 `next`、`mastered`、`lastPracticed`、`overdue`（L5220）——**深度其实已经在表格里算过一次**，图里又用 `todayNo - dayIndexOf(n)` 算第二次（L5466）。两处算法相同但各写一遍，正是这个项目反复栽过的口径分裂形状。
- 表格侧对畸形数据有一道兜底：mastered 但既无 `lastPracticed` 又无 `masteredAt` 时，`effectiveNextOf` 会把时间落到 1970 年附近，表格把这类题的 `overdue` 强制为 0（L5215-5216），注释写明否则报表会出现「逾期两万天」。图侧**没有这道兜底**，走的是自己那套减法。
- 第 0 列现在同时是三种东西：今天到期（`idx === 0`）、全部逾期（`idx < 0`）、从未排期（`!n`，L5463）。合并发生在 L5471 `buckets[0] += overdue`。
- 峰值 `peakIdx = buckets.indexOf(max)`（L5474）因此被第 0 列的堆带偏，输出「📅 峰值 今天 · N 题」（L5489-5490）。
- 三处现有断言直接锁住这些写法，改代码必须同轮改它们：列数按 `/<i class=/g` 计数（smoke-test L564）、第 0 列必须含 `today` 子串（L694）、静态匹配源码文本 `if(idx < days) buckets[idx]++; else later++;`（L836）、`✅ N 天内无排期` 的措辞且不得写成「未来无排期」（L568）。
- 总览卡的 `todo = due + fresh`（L3476）算出来后只进了 title 悬浮提示（L3511），卡面是「大数 due + 小字 未学 N」（L3512-3513）。顶部统计条反倒已经把两者作为两个平级 chip 显示（L3404-3405）——**同一页面内两处口径权重不一致**。

## Goals / Non-Goals

**Goals:**

- 让到期预测在「大面积逾期」这个极端场景下仍然说得出信息。
- 深度计算只保留一处实现，图与表格共用，畸形数据的兜底同时生效。
- 卡面数字与记忆模式队列总数可以互相核对。

**Non-Goals:**

- 不改变 `sum`（窗口内总数）的定义：仍是各列之和、含并入当日的逾期，窗口外的题继续单独脚注。拆分只发生在列内部，不动总量口径。
- 不新增列、不改窗口天数的来源（`days` 依旧等于 `FSRS_MAX_INTERVAL`）。
- 不给「未学」加告警色，也不把 `ov-act` 脉冲的触发条件从 `due > 0` 改掉。理由：未学不催命，同时亮两处会稀释真正该扎眼的信号。
- 不引入任何每日配额或队列裁剪（与 change `memory-surface-readability` 同一立场）。

## Decisions

### D1：第 0 列仍是一个 `<i>` 节点，内部分段用硬色标渐变

逾期分段不通过嵌套子节点实现，而是在同一个 `<i>` 上用 `linear-gradient` 的硬色标切出各段占比。

- **为什么**：既有断言用 `/<i class=/g` 数出 14 列（smoke-test L564），`.fc-strip > i` 的样式也按「一列一个节点」写。嵌套子节点会同时打断断言与样式，还会让 `fc-empty` 那个「不能用 `.empty`，否则会命中全局空状态把空柱撑到 120px 冲出容器」的既往坑（L5481-5483 注释）有机会复发。
- **保留 `today` 类**：第 0 列的 class 继续含 `today` 子串（断言 L694 依赖），分段信息放在 `data-seg` 与 `title` 上。
- **替代方案（已否）**：把逾期拆成图外独立一行或额外一根柱。改动列数与总数语义，风险面明显更大。

### D2：深度计算只留一处，图直接消费 rows 已有的 `overdue`

新增共享小函数 `overdueOf(r, todayNo)`，规则：

```
r.overdue > 0            → 逾期，深度 = r.overdue
r.mastered 且无时间戳     → 深度 0（沿用表格 L5215 既有兜底，杜绝「欠两万天」）
!r.next 且非 mastered     → 归为「从未排期」，不进逾期
其余                      → 由 dayIndexOf(r.next) - todayNo 判定，负数才算逾期
```

- **为什么**：现在图与表格各写一遍减法（L5466 与 L5216），而兜底只有一边有。这正是 `effectiveNextOf` 当年被抽成共享函数的同一个理由。
- **代价**：冒烟里手工构造 rows 的几个用例只带 `next` 字段（`at(d) => ({ next: ... })`，L561），改完必须给用例补上 `overdue` 等字段，属于「改代码同步改断言」，已在 tasks 列出。
- **替代方案（已否）**：图继续自算。等于把一个已知的口径分裂写进规格还留着它。

### D3：三类分开计数，未排期不进「窗口内总数」

`buildForecastHtml` 内部产出 `{ today, overdueSeg:[a,b,c], undated, later }`：

- 未排期题没有「哪天到期」这个属性，硬塞进「未来 N 天共 X 题」会让那个数字继续说谎（这正是本 change 要修的第二个毛病）。它们改由脚注单列：「另有 W 题从未排期，进队列但无到期日」。
- 逾期三段边界 = `FSRS_MAX_INTERVAL` 与 `2 × FSRS_MAX_INTERVAL`，**由上限推导而不写死数字**，这样上限再变时界随动（specs 里「边界随上限走」那条场景就是为它写的）。
- 三段常量若 change `memory-surface-readability` 已先落地，则复用其声明，不在这里重复一份；本 change 先做时由本 change 声明、另一处引用。两个 change 都单独声明一遍是最坏结果。

### D4：峰值只取未来列，逾期另起一句；`sum === 0` 分支文案不动

```
未来列（idx ≥ 1）有题  → 峰值 = 其中最大者，逾期不参与
未来列全空但有逾期      → 新分支：「今天之后 ${days} 天内无新排期 · 欠账 N 题」
sum === 0（无任何排期） → 保留原样「✅ ${days} 天内无排期」
```

- **为什么保留最后一支原样**：断言 L568 同时要求含 `14 天内无排期`、且不得出现 `未来无排期`。第一支的新措辞用「今天之后 … 无新排期」，不与该断言冲突，也不与旧文案混用。

### D5：总览卡把两个数做成同等字重的一行

卡面结构改为「到期 N · 未学 M」两个同等字号字重的数字并排，下方一行给出等式「复习队列 = N + M」（即把已有的 `todo` 第一次真正显示出来）。大数字位仍归 `due`，颜色逻辑（`due>0` 用 `--warn`，否则 `--good`，L3512）与 `ov-act` 脉冲条件不变。

- **为什么不塞成第五张大数卡**：`.ov-grid` 的五张卡是既有节奏，加一张会挤版心；等式那一行才是本次真正缺的东西。
- **无障碍**：`todo` 等式是纯文本，读屏自然读到；不新增 aria 语义。

### D6：逾期语气与 change 1 同调

`--bad` 用于「出错/危险」，长期欠账不属于它。本 change 把预测图脚注的逾期色（L5489 写死的 `var(--bad)`）与卡面告警一起降为 `--warn`/中性，与 `memory-surface-readability` 对记忆卡头部的处理一致。两处若分头实施，同一件事会在两个页面情绪不一致。

## Risks / Trade-offs

- **[断言连锁破裂]** 列数、`today` 子串、总数文案、无排期措辞、静态源码匹配这五条都会同时受影响 → **缓解**：把「同轮改断言」写进 tasks，改完立刻 `npm run verify`，不留中间状态。
- **[硬色标分段在极窄列上读不出]** 7 列时第 0 列约 1/7 宽，段高差小于几像素就看不出 → **缓解**：占比低于阈值的段不画，但数字仍在 `title` 与脚注里报出——宁可少画一段，也不要给出看着一样高的假精确。具体阈值留实现时按实测定。
- **[未排期从总数里挪走，老数字变小]** 用户可能以为题丢了 → **缓解**：脚注显式给出未排期数，等式让三个数能加起来对得上；specs 的「总量不因拆分而改变」那条正是要求这件事可核对。
- **[共用 `overdueOf` 动了表格侧计算]** 有把表格 `overdue` 算错的风险 → **缓解**：函数以「表格现有结果」为准绳写回归断言（含 mastered 无时间戳那一例，期望值 0），改完两条都必须通过。
- **[Trade-off]** 第 0 列仍与「今天到期」共柱，视觉上无法像真正的双柱那样分明；换来的是不断列数语义、不动样式结构、不碰 `fc-empty` 那个坑。

## Migration Plan

1. 先落 `overdueOf` + 表格侧改为调用它（行为不变，先让回归断言锁住现状）。
2. 再改 `buildForecastHtml`：三类计数 → 三段逾期 → 渐变分段 → 峰值只取未来列 → 脚注文案。
3. 同轮同步 smoke-test 里被影响的所有断言与 rows 构造。
4. 总览卡结构（D5）。
5. 版本号双写 `SW_VERSION` / `CACHE`，跑 `npm run verify`。
6. **回滚**：纯展示层，无数据迁移，`git revert` 即可。
