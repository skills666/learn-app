# 什么是反射？为什么反射性能会比较差一些？反射一般用在什么场景？

反射是在运行时动态获取类的信息、操作类的属性和方法。

补充：不需要在编译时知道具体类名，正常写代码编译时就知道要调什么方法，反射运行时才知道，反射的入口是Class对象，JVM加载类的时候自动生成。

反射性能差主要是两个原因。第一，正常调方法 Java 在编译时就确定好了，直接跳过去执行就行。反射是运行时才知道要调谁，每次调用都要先检查，这个类能不能访问、这个方法存不存在、权限够不够，一套查下来本身就慢。第二，基本类型会被反复装箱拆箱，产生额外对象和 GC 开销。

一般用在框架底层，Spring的IOC实例化Bean、依赖注入、AOP动态代理，Mybatis的结果映射，全是反射。

# 什么是代理？静态代理和动态代理的区别是什么？jdk动态代理和cglib的区别是什么？

代理是不直接访问目标对象，通过一个代理对象间接访问，可以在调用前后添加额外逻辑。

静态代理和动态代理的区别：

静态代理：在编译前就写好了，需要手动创建，每代理一个类就要手写一个代理类，维护成本爆炸。

动态代理：代理类在运行时动态生成，不需要手动写代理类，一个代理处理器可以代理任意接口，不需要为每个类写代理类。

jdk动态代理和CGLIB区别：

jdk动态代理是基于接口，被代理的类必须实现至少一个接口；运行时动态生成了一个实现了所有接口的代理类，内部通过反射调用目标方法。

CGLIB是基于继承，不需要接口，通过生成目标类的子类来实现代理；生成目标类的一个子类，重写所有非final的方法，在重写方法里调用拦截器。

补充：Spring中有接口时两种都能用，没接口只能用CGLIB。SpringBoot2开始默认用CGLIB，避免jdk代理转具体类的类型转换问题。

# ==和equals的区别？两个都重写的情况，equals相等hashcode一定相等吗？hashcode相等equals一定相等吗？什么场景需要同时重写equals和hashcode方法？具体怎么重写equals方法和hashcode方法？

==在比较基本类型时，比较的是两个变量的数值是否相等。比较引用类型时，比较的是内存地址。

equals是Object类的方法，默认行为也是比较地址，但是很多类都会重写equals方法，变成比较内容是否相等。

都重写的情况下，equals相等hashcode一定相等，因为hash集合是根据hashcode找桶，再equals判断，如果equals相等hashcode不相等，同一个对象会被存到不同的桶里，导致逻辑错误。

把对象当做HashMap或HashSet的key时，如果不重写hashcode和equals，默认情况下两个属性一致的新对象，hash值不一样，集合会判定为两个不同的对象，没法实现去重效果。规范要求，只要重写了equals，就必须同步重写hashcode，确保内容相同的对象，hash值也保持一致。

equals重写的标准写法就是先判断两个引用是否相等，相等直接返回true，再判断传入对象是否为null或者类型不匹配，直接返回false，然后把对象强转为当前类型，逐个比较关键属性。

Hashcode的重写一般就把关键属性算出一个hash值返回。

# Integer i1 = 127;Integer i2 = 127;i1==i2？Integer i1 = 127;Integer i2 = 127;i1.equals(i2)？Integer i3 = 128;Integer i4 = 128;i3==i4？Integer i3 = 128;Integer i4 = 128;i3.equals(i4)？int i5 = 128;Integer i6 = 128;i5==i6？Integer i = 128和Integer i = new Integer(128)有什么区别？

true：Integer i1 = 127编译后等价于Integer.valueOf(127)，Integer.valueOf 内部有一个缓存池，范围是 -128 ~ 127，127 在范围内，直接从缓存取，两次拿到同一个对象。

true：equals比的是值，不拆箱，Integer重写了equals方法，比的是内部的int值。

false：超出缓存范围-128~127，valueOf直接new Integer(128)，两次调用生成两个不同的对象，==比较地址，所以为false。

true：当==一遍是基本类型，一遍是包装类型时，包装类型会自动拆箱再比较。

都是128就没区别，都会new一个新对象，如果是127，直接赋值会从缓存取，但是new会绕过缓存，必定创建新对象。

补充：new Integer() 从 JDK 9 开始被标记为 @Deprecated，推荐用 Integer.valueOf()，所以现在不应该再用 new Integer 了。

# String、StringBuilder和StringBuffer的区别

String不可变，每次对String的操作都会在内存中创建一个新的对象；性能很低但是线程安全，因为不可变，所以适合多线程。

StringBuilder可变，操作会直接修改原对象，不产生新对象。方法没有锁修饰，性能很高但是线程不安全，适合单线程环境。

StringBuffer和StringBuilder相同，但是方法加了锁，性能略低于StringBuilder；适合多线程环境。

# 接口和抽象类的区别

抽象类：是不完整的类，单继承；可以有普通变量，有抽象方法和普通方法，还有构造方法；方法可以是各种权限；用于代码复用和模板方法，适合相关类有共同实现。

接口：是一种规范，多实现，JDK8 及以上接口之间还支持多继承；只能有常量；JDK8 之前只能有抽象方法，JDK8 之后可以有默认方法和静态方法；没有构造方法，方法默认 public；用于定义能力、解耦、规范，适合完全不同的类拥有相同行为。

# 说一下java面向对象的三大特性

封装：将对象的属性和方法封装到一个类里，隐藏内部实现细节，仅对外开放有限的访问接口。

继承：类通过extends实现单继承，子类复用父类代码，搭建类之间的层级体系；

多态：同一行为可以有多种表现形式，类的多态依托继承与方法重写；接口多态用implements多实现，不同实现类呈现差异化业务逻辑，JDK8接口新增默认方法可扩展接口功能，有效实现代码解耦。

补充：多态的前提

要有继承/实现关系

要有方法重写

父类引用指向子类对象

# 说一下线程本地变量ThreadLocal的作用，在项目中一般用来做什么？使用上要注意什么？

ThreadLocal就是给每个线程一个独立的变量副本。同一个ThreadLocal对象所有线程独享自己的数据。

主要用来存用户的登录信息，请求进来，拦截器从 token 里解析出 userId，塞进 ThreadLocal，后面 Controller、Service、DAO 一整条链路上随时取，不用每层都传参数。

就一个核心问题：内存泄露。ThreadLocalMap里的key是弱引用，被GC回收后就变成null了，但value是强引用，线程不死它会一直在。必须手动remove。项目里的做法就是在拦截器的afterCompletion里把ThreadLocal清掉，一个请求处理完立刻清理，百分百不漏。

# 说一下重写和重载的区别

重写是实现多态的核心，发生在继承关系中，比如子类重写父类允许访问的方法，其方法名、参数列表必须相同，返回类型可以是父类返回类型的子类，访问权限不能更严格，只能相同或更宽。

重载发生在同一个类或父子类之间，多个方法同名，与返回类型无关，只改返回类型不能重载。

# jdk的新特性有哪些？

jdk8加入了lambda表达式，可以简化匿名内部类，让代码更简洁。还有Stream流，可以对集合进行链式操作，简化了对集合的处理。

Jdk11支持var用于Lambda参数类型推断；自带http客户端，无需第三方工具就能发起网络请求。

Jdk17新增了密封类，限制了谁能继承它，防止类型体系被意外扩展。

Jdk21推出了虚拟线程，属于轻量级线程，由虚拟机调度，能支撑大规模并发场景，IO密集型业务可以有效提升程序的吞吐量。

# 介绍一下final关键字

final是一个修饰符，可以修饰类、方法、变量。

修饰变量的时候，这个变量就变成常量，只能赋值一次，如果修饰的是引用类型的变量，地址不可变，对象里的内容可以变。

修饰方法的时候，方法不能被子类重写，一般用在不想让子类改变核心逻辑的场景。

修饰类的时候，这个类不能被继承，像String、Integer这些包装类都是final类，目的就是保证安全、不可变。

# 说一下浅拷贝和深拷贝的区别，怎么实现浅拷贝？怎么实现深拷贝？

浅拷贝是只复制对象本身，内层引用对象还是同一个，修改拷贝的对象原对象也会变，性能快。

深拷贝就是把整个对象图递归复制，两个对象完全独立，递归开销大，性能慢。

浅拷贝实现Cloneable接口调clone()或者用拷贝构造器就行。

深拷贝简单的对象手动递归clone，复杂对象用序列化反序列化或JSON转字符串再转回来。
