# 对称加解密和非对称加解密的区别是什么？分别有哪些算法？签名是解决什么问题？签名算加密吗？编解码和加解密的区别是什么？

对称加解密和非对称加解密的区别：

对称加密：加密和解密用同一把钥匙。发送方用这把钥匙把数据加密，接收方用同一把钥匙解密。快，适合加密大量数据。但问题是怎么把钥匙安全交给对方——钥匙传过去的过程本身就是安全风险。

非对称加密：两把钥匙，一把公钥一把私钥。公钥公开给所有人，私钥自己留着。用公钥加密的数据，只有对应的私钥能解开。反过来，用私钥加密的数据，公钥也能解开。比对称加密慢很多，一般不用来直接加密大量数据，而是用来安全传递对称加密的钥匙。

分别有哪些算法：

对称加密：AES（最常用）、DES（老，已淘汰）、3DES（DES 加强版，也基本不用了）

非对称加密：RSA（最经典）、ECC（椭圆曲线，效率比 RSA 高）、SM2（国密标准）

签名解决三个问题：防篡改、身份认证、不可否认。举个例子，JWT 第三段就是签名，服务端用 secret 签出来，客户端改内容就过不了验签。

签名不算加密。加密是为了让别人看不到内容，签名是为了证明内容没被改过、是我发的。虽然签名的过程用了加密算法，但目的完全不同。加密能解密还原原文，签名生成的是摘要，没法还原回去。

编解码和加解密的区别是什么？

两者算法都是公开的，最大区别是加解密需要密钥，编解码不需要。编解码只是格式转换，让数据能在不同系统间传输，比如 Base64，没有任何安全性。

# 说一下常用的排序算法和平均时间复杂度，说一下快排的思路，说一下二分查找的思路

### 常用排序算法和时间复杂度

冒泡排序：O(n²)。两个相邻的比，大的往后走，每轮把最大的冒到最后。

选择排序：O(n²)。每轮找最小的放到最前面。

插入排序：O(n²)。像打扑克理牌，拿一张插到已排好的位置里。

快速排序：O(n log n)。选一个基准值，小的放左边、大的放右边，然后左右分别递归。

归并排序：O(n log n)。先对半拆到不能再拆，再从下往上两两合并。

堆排序：O(n log n)。建一个大顶堆，每次取堆顶放最后，剩下的重新调整。

面试记住三个 O(n log n) 的快归堆加一个 O(n²) 的冒泡就够了。如果不要求稳定就先选快排，实际开发中就用现成的 Arrays.sort()，内部也是快排。

### 快排的思路

从数组里挑一个基准值，一般就选第一个。

从头尾两端往中间扫。左边找比基准大的，右边找比基准小的，找到就交换。一直扫到左右指针碰上。

指针碰上的位置就是基准的最终位置——左边全比它小，右边全比它大。

基准左右两边各自再递归做同样的事。一直拆到子数组只剩一个元素，整个数组就有序了。

快排的平均时间复杂度是 O(n log n)，最坏情况是每次基准都选到最大或最小值（原本就有序的数组），退化成 O(n²)。优化方法是随机选基准，不固定选第一个。

### 二分查找的思路

前提是数组必须有序。每次取中间位置的值和目标值比较：

相等 → 找到了，返回位置

中间值比目标大 → 目标在左半边，缩小范围到左边

中间值比目标小 → 目标在右半边，缩小范围到右边

每次砍掉一半，时间复杂度 O(log n)。重复这个过程直到找到或者范围缩到没元素了返回 -1。

# 说一下为什么需要雪花算法id的存在？说一下雪花算法id的组成及每个部分的作用，怎么解决时钟回拨的问题？

分布式ID生成方案有很多种，比如数据库自增主键、Redis原子自增、UUID。但如果要满足几个特定要求——固定位数、纯数字、还要趋势自增——这些方案就各有各的问题了。

自增主键在单库没问题，分库分表后多个库各自自增，ID会重复。Redis原子自增也能保证唯一，但集中在Redis上生成，高并发时Redis有压力。UUID能保证全局唯一，但它是无序字符串，做主键会导致B+树频繁分裂，写入性能差。

雪花算法正好解决这些问题。它生成的ID全局唯一、趋势递增、纯数字，而且每个节点自己在内存里生成，不用集中式依赖数据库或Redis，横向扩展方便。

为什么是趋势自增而不是严格自增呢？因为严格自增有可能被竞争对手根据前后订单ID差值推算出你的业务订单量，趋势自增能避免这个问题。

雪花算法是Twitter发明的，名字来源于"自然界没有两片完全相同的雪花"。ID由64位二进制组成，也就是19位十进制数，分成四个部分：

第一位是符号位，固定为0，保证ID永远是正数。

第2到42位共41位，是毫秒时间戳。一般从1970年算起能用69年，实际项目里可以改成从系统上线时间算起，一个系统很难用几十年，完全够了。

第43到52位共10位，是机器ID，最多支持1024台机器同时生成不重复的ID。如果有机房概念，也可以把10位再拆成机房ID加机器ID。

第53到64位共12位，是序列号，同一台机器同一毫秒内递增，最多4096个。换算下来一秒可以生成4096万个ID，除非天文数字的科学计算，否则完全够用。实在不够的话，可以从机器ID的位里挪一部分给序列号，因为一般也没有那么多机器。

时钟回拨是指服务器时间不小心被回调到过去的时刻，可能导致雪花算法生成重复ID。最直接的解决方式就是在数据库加唯一约束。雪花ID一般用作主键或唯一键，插入重复了数据库直接报错，重新生成一个就行。
