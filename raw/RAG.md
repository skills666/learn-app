# RAG 影响准确度的因素有哪些？

主要有九个。

第一个是数据清洗，如果给模型的文本不干净，搜出来的结果也偏。

第二是分片，切太大，一块内容太多，语义就不精准；切小的上下文会段。

第三是向量维度，维度越高语义越细，但存储和计算的开销也大。

还有三个是检索环节直接决定搜的准不准的，相似度算法、相似度阈值、一次返回几个分片。阈值太高容易漏召，太低召回一堆不相关的；返回太少信息不全，太多又会有噪声。

再就是query改写，用户问的很口语化、带错别字，要不要先优化成规范问题再检索，直接影响能不能搜到。

最后就是向量模型本身的质量和文件解析质量。模型不同，同样的文字算出来的向量质量不一样；文件解析要是拉跨，比如PDF扫描件没做OCR，整份内容直接丢了，后面都白搭。

# 分片有哪些策略？父子块是什么？

最常用的是递归字符分片，就是按段落、句号、逗号、空格、逐字，一级一级往下拆，拆到不超过最大字符数就停，尽量不把完整的一句话斩断。

还有按层级标题分片，适合 Word、MD 这种有标题层级的文档，直接按最小标题拆，本身就符合语义。

父子块是在递归分片基础上再拆一层。先把文档按正常粒度切成父块，再把每个父块用同样办法拆成更小的子块。子块向量化后用于精准搜索，搜到子块后通过它记录的父块地址把完整的父块拿来当上下文喂给大模型。这样搜索精准度高，大模型看到的上下文也完整。

# 什么是向量化？为什么要转向量？

向量化就是把把文字、图片这种非结构化的东西，转成一串数字。

因为计算机只能判断数字是否相近，没法判断两段文字语义是否相近。转成向量后，意思相近的两段文字算出来的数字串也相近，就可以用数学公式（余弦相似度、欧氏距离）来做语义检索了。同一个文本用同一个模型算多次，结果是一样的，也是稳定的。

# 向量数据库的索引类型有哪些？有什么区别？

主要有四种，核心就是精度和速度的取舍。

最准的FLAT 是暴力搜索，拿查询向量跟库里面每一个向量逐条比对，精确度最高但效率最低，适合数据量小的场景。

然后是IVF_FLAT 先把所有向量聚成几簇，查询时只搜索最接近的几个簇，速度快、精度有损失。

IVF_SQ8 在 IVF_FLAT 基础上加了标量量化，把每个浮点数从 4 字节压缩到 1 字节，省存储但精度再降一点。

IVF_PQ 是乘积量化，把向量拆成多个子向量分别压缩，存储最小、适合十亿级超大规模，精度损失也最大。总的来说就是精确度和效率的权衡。

# 数据清洗做了什么？

去掉特殊字符、多余空白、控制符、页眉页脚、无效行、重复段落。HTML 里的转义空格； 核心就是保证喂给模型的是干净的纯文本。但也要适度，洗太狠可能把有意义的格式也洗掉，影响语义。

# 不同文件类型（Word/PDF/Excel/图片）怎么处理？

TXT 直接用递归字符分片。

Word 和 PDF 分两种情况：纯文本没标题的按递归字符分片；有层级标题的直接按最小标题拆。

Excel 每行一个分片。PPT 每张幻灯片一个分片。

Markdown 和 HTML 跟word一样，有标题层级按标题拆。图片用 OCR 提取文字，一个图片一个分片。

所有文件类型如果里面嵌了图片，图片单独拆出来作为一个独立分片。

# 分片重复怎么处理？

分两情况。同一个文件内出现相同的分片，直接在分片阶段去重，留一个就行。不同文件出现相同的分片，内容可以合并成一个，但元数据里要保留多个文件来源，方便追溯。不能直接删掉其中一个，因为两个文件各自都可能被用户单独检索到。

# 图片、音频、视频怎么参与 RAG？

图片用 OCR 提取文字，再走多模态模型识别图片本身的含义，也就是图生文。

音频提取文字内容、时间戳、说话人，交给多模态模型处理，一般不需要单独识别音频本身的含义，因为含义已经在文字里了。

视频最复杂，音频部分参考音频策略，画面里的文字用 OCR 提取，视频本身的含义（比如"这是室外场景"）用多模态模型识别。这些提取出来的文本都像普通文档一样向量化存入向量库，用户搜"室外的相关视频"也能命中。

# 什么是混合检索？

向量检索加全文检索一起用。向量检索靠语义相似度，能搜到意思相近但用词不同的内容，比如搜"退款"能命中"退费规则"。全文检索靠关键词匹配，能精准搜到包含特定术语的内容——比如搜"订单编号"直接命中。两者互补，语义检索覆盖面广，全文检索精准不跑偏。混合检索就是把两边的结果按权重合并排序，既能搜到相关的内容，又不会漏掉精准匹配的结果。

# RAG 除了直接搭流水线，还有什么实现方式？

还有一种方式是把 RA G 包在 Tool Calling 里面做。在系统提示词里写"如果用户问题需要查资料，先调用查询工具"，工具内部去向量数据库检索，返回结果再交给大模型作答。

区别是，直接搭流水线是每次请求自动走 RAG 流程，Tool Calling 方式是大模型自己判断要不要查、什么时候查，更灵活但也多了一次判断开销。
