# 集合

# 项目中常用哪些集合？

项目中主要用ArrayList存普通列表数据，HashMap做缓存或快速查找，HashSet用来去重。并发场景下会用ConcurrentHashMap。

# 说一下List、Set和Map的区别？

List是单列集合，有序，允许重复，也支持索引访问元素。

Set也是单列集合，不可重复，可以有序也可以无序，要看具体的实现类，比如HashSet就是无序，TreeSet是有序，不支持索引访问元素。

Map是双列集合，存储键值对，key不允许重复，value可以重复，可以通过key访问value，可以有序列也可以无序，比如HashMap是无序，TreeMap是有序。

# 说一下HashMap的底层原理

底层结构：HashMap在jdk8之前用的是数组+链表，在jdk8之后用的是数组+链表+红黑树。数组的每个下标称为桶，存入键值对时会先算出key的哈希值，来确定该放在哪个桶，如果多个key哈希值相同，冲突的元素会以链表的形式挂在同一个桶。当链表长度大于等于8，数组长度大于等于64时，链表会转换成红黑树，查询效率更高，链表节点数降到6会退回链表，节省内存开销。

Hash算法：HashMap确认一个key的位置过程，首先调用key的hashcode得到一个32位的哈希值，把这个hashcode高16位与低16位做异或，这样高位的信息也混合进去，可以减少哈希冲突，这个操作叫扰动函数。之后用扰动后的哈希值对数组长度取模，也就是(length - 1) & hash，因为HashMap的数组长度都是2的幂次方，所以可以用位运算代替取模，效率更高。

扩容机制：HashMap是懒加载的，第一次put元素时才会初始化数组，默认长度是16，元素个数超过阈值时才会扩容，阈值的计算方式是数组长度 * 0.75，如果数组长度是16，超过12个元素的时候就会扩容成原来的两倍，旧数组中同一个链表上的元素，在新数组中只可能落在原下标或原下标+旧容量，不需要重新计算hash。

HashMap线程不安全，并发场景易出现死循环、数据丢失等问题，所以要用ConcurrentHashMap。

# HashMap是线程安全的吗？那想要线程安全怎么办？

不安全，多线程put会导致数据丢失，put和get同时进行可能get到null，HashMap所有方法都没有加锁。

可以用现成的工具类，比如ConcurrentHashMap

或者HashMap用于局部变量，不要用于全局变量，这样就不涉及多线程同时访问，也就不会有线程安全的问题。

也可以把HashMap放在ThreadLocal里使用，这样每个线程独享自己的数据，也不会有线程安全问题。

# HashMap查找的时间复杂度是多少？

最好的情况，也就是没有哈希冲突，直接命中桶里那个元素，时间复杂度是O(1)。

最坏的情况，如果所有元素都哈希冲突到同一个桶，在jdk8之前查找要遍历整个链表，时间复杂度是O(n)，但在jdk8之后链表和数组超过阈值会转成红黑树，红黑树的查找复杂度是O(log n)。

平均情况，假设哈希函数分布均匀，每个桶里元素接近，时间复杂度基本是O(1)。

补充：因为红黑树是自平衡二叉查找树，查找效率稳定在树的高度，也就是log n。

# HashMap是有序的吗？什么Map是有序的？

HashMap是无序的，遍历HashMap时，键值对的顺序和插入顺序不一样，因为它是根据key的哈希值决定桶的位置，不同key的哈希值不同，放进去的顺序和取出来的顺序天然不一样。

有序的Map有LinkedHashMap，它在HashMap的基础上维护了一个双向链表，记录了插入顺序或访问顺序，默认是插入顺序；如果把访问顺序打开，每get一个元素，这个元素就会被移到链表末尾，这种模式可以用来实现LRU缓存。

还有TreeMap，按照key的自然顺序或自定义的Comparator比较器排序，遍历TreeMap时拿到的顺序是排好序的。

# HashMap为什么扩容是2倍？为什么扩容因子是0.75？当数组长度少于64，链表长度大于等于8会怎么样？HashMap能自动缩容吗？

因为和取模运算的优化有关，HashMap定位元素位置，用的是hash值对数组长度取模，但当长度是2的幂时，可以用位运算代替，位运算比取模快，扩容时如果仍然是2的幂，这个优化才能持续生效。

还有扩容时元素迁移效率更高，旧数组中同一个链表上的元素，在新数组中只可能落在原下标或原下标+旧容量，不需要每个元素重新计算hash。

为什么负载因子是0.75：如果扩容因子偏大，空间利用率是高了，但是哈希冲突概率增加，链表变长查询也会变慢；如果偏小，冲突少了，查询也快了，但是扩容频繁空间浪费严重。0.75是官方经过概率测算的平衡点，在保证查询性能的前提下，将空间利用率维持在可接受水平。

当数组长度少于64，链表长度大于等于8会怎么样：会优先扩容数组，数组还很小时，链表过长很可能是数组容量不足导致hash冲突集中，扩容数组能从根本上分散元素，比转红黑树更合理。

HashMap能自动缩容吗：不能，HashMap没有自动缩容机制。

# new HashMap()初始底层数组长度是多少？new HashMap(14)初始数组长度是多少？

new HashMap()的初始数组长度是0，只有在第一次put时才分配空间，默认容量是16。

new HashMap(14)初始数组长度为0，传入initialCapacity = 14时，构造器调用tableSizeFor计算实际容量，会找到大于等于14的最小的2次幂，也就是16，先把 16 暂存到 threshold；首次 put 初始化数组长度为 16。

二者都是懒初始化，区别在于有参构造预先算好了扩容阈值。

# 什么时候链表会转成红黑树？什么时候红黑树会转成链表？为什么是6和8？

链表长度大于等于8同时数组长度大于等于64的时候会转成红黑树。

红黑树节点数小于等于6的时候会退化为链表。

链表转红黑树的阈值时8：负载因子为0.75时，正常情况下一个桶中链表长度到8的概率极低，如果达到8说明hash冲突已经很严重了，需要用红黑树来优化查找效率，避免链表退化的性能问题。

红黑树退回链表的阈值是6：因为需要一个缓冲区，如果都是8，节点数在789之间反复增删，会导致链表和红黑树频繁互转，性能开销大，所以降到6才退化链表，给了一个7的缓冲带。

# 为什么选择红黑树，而不是二叉树、平衡二叉树和B+树？

普通二叉树没有自平衡机制，极端情况下退化成链表，查找从O(log n)变成O(n)，HashMap要的就是解决链表太长的问题，换成二叉树还可能变成链表，等于没解决。

平衡二叉树是严格平衡，任何节点左右子树高度差不超过1，每次插入都可能触发多次旋转，转来转去开销大，省下的查找时间抵不上旋转的消耗，红黑树牺牲一点点平衡性，换来插入删除的大幅提速更划算。

B+树是专门为磁盘设计的，节点太大，内存场景用不上。

# HashMap直接做缓存有没有不足的地方？

有几个致命问题：

没有过期淘汰机制，存进去的数据永远都在。

没有淘汰策略，内存会无限增长。

没有缓存穿透保护。

线程不安全。

# jdk1.7的HashMap采用头插法会造成什么问题？怎么解决？

扩容时并发put可能形成环形链表，造成死循环，拉满CPU。

假设桶链表A-B-null，两个线程同时触发扩容，线程1指向A，next指向B，还没迁移就被挂起了，然后线程2完整执行了扩容，这时候内存真实结构是B-A-null，线程 1 恢复执行，它手里是 A，next 还是 B。先把 A 插入新链表，A.next 先指 null。然后继续处理 B。但此时 B 已经被线程 2 改过了，B.next 指向 A。于是 B.next = A，A.next 又被后续步骤改写回 B，形成 A → B → A → B 的闭环，null 彻底消失。

jdk1.8改成了尾插法，每次把新节点接到链表尾部，保持原顺序，扩容时不会改变链表节点的原有顺序，并发操作最多数据丢失(少一个节点)，但不会出现环形链表。

# 说一下ConcurrentHashMap的底层原理

jdk8之前用的分段锁，核心思想是把整个数组拆成Segment，每个Segment独立加锁，不同的Segment之间可以并发操作；put/remove时对自己上锁，每个Segment内部就是一个小HashMap。

jdk8抛弃了Segment，和HashMap一样的结构，锁粒度缩小到单个桶；put时计算key的hash定位数组下标，判断该位置是否为null，是null就CAS直接写入，成功就结束，不是null就synchronized 锁住该桶头节点，然后判断头节点类型，如果是链表就遍历，存在就替换，不存在就尾插；如果是红黑树就走树的插入逻辑；之后判断链表长度 ≥ 8 且数组长度 ≥ 64 才转红黑树，否则扩容；扩容时支持多线程协助迁移数据，最后解锁。

# 说一下ConcurrentHashMap和HashTable的区别

HashTable：

使用synchronized修饰方法锁住整个表，底层是数组+链表，并发读写要排队等锁，单线程扩容，扩容时整个表锁死。

ConcurrentHashMap：

用CAS+synchronized锁住单个桶，put时算出key的hash定位数组下标，桶为空直接CAS无锁写入，桶有数据synchronized锁桶头节点，读操作不加锁；底层是数组+链表+红黑树，多线程同时读不阻塞，多线程协同扩容，扩容期间仍然可以读写；在所有维度上都碾压HashTable，所以HashTable现在基本不用了。

HashTable和ConcurrentHashMap的key和value都不能为null。

# 说一下HashSet的底层原理

HashSet底层就是一个HashMap，把要存的元素作为HashMap的key，value是个固定的object对象；利用HashMap的key不能重复的特性来保证元素不重复，判断重复靠的是hashCode和equals方法，先比 hashCode，不同就不重复；相同再调 equals，也相同才算重复。

# HashMap的key和value可以为空吗？如果可以允许key为null，那么这个元素是存在哪个桶？ConcurrentHashMap和HashTable的key和value为什么不可以为空？

都可以，key允许一个null，value允许多个null。

key为null时，HashMap会把hash值处理成0，所以这个元素存放在数组的第0号桶。

ConcurrentHashMap在并发环境下如果允许为null，get方法返回null时，没法区分是key不存在还是value就是null。

HashTable底层代码直接调用key.hashCode()，传入null直接抛空指针异常，属于历史设计，没有做null兼容。

# 说一下ArrayList和LinkedList的区别

ArrayList底层是Object数组，数组下标可以直接定位，访问速度快，但是中间插入和删除慢，会移动被操作下标之后的所有元素；初始容量是0，第一次add时才变成10，扩容倍数是原长度的1.5倍；适合频繁查询。

LinkedList底层是双向链表，每个节点存前后指针，头尾操作快，中间插入删除如果已定位到节点才快，否则也要遍历，但是随机访问慢，需要遍历。

补充：LinkedList 同时实现了 List 和 Deque 接口，既能当列表，也能当双端队列/栈用。

# new ArrayList()数组初始长度是多少？new ArrayList(3)数组初始长度是多少？

new ArrayList()是无参构造，初始长度是0，只有在第一次add的时候才会初始化长度为10，这是懒初始化，防止创建了ArrayList又不用，浪费内存。

new ArrayList(3)是有参构造，初始长度就是3，能预估数据量时就用这个，能避免频繁扩容。

# ArrayList和LinkedList是线程安全的吗？线程安全的List有哪些？

ArrayList和LinkedList都不安全，两者都没有任何同步机制，多线程并发读写会出现数据不一致、索引越界等问题。

线程安全的List有：

Vector：所有方法都加了synchronized，读写全串行，性能差。jdk1.0的产物，已经被淘汰了。

Collections.synchronizedList包装后的ArrayList，所有方法自动加锁，比Vector好一点，但也是全表锁，遍历时要手动加锁，不然会抛ConcurrentModificationException。

CopyOnWriteArrayList：写操作加 ReentrantLock，保证同一时刻只有一个线程在写，每次写入都会复制一份新数组，在新数组上操作后替换旧数组；优点是读没有锁，并发性能高，数据一致性是最终一致；但是写要复制整个数组，内存占用翻倍，不适合频繁写的场景。

适合场景：读多写少，比如黑名单、白名单、配置列表。

# 用下标循环，边循环边删除List的数据会有什么问题？有哪些方案可以解决？

边循环边删除索引会错乱，导致漏删或越界；因为每次删除后，当前下标后面的元素会前移。

解决方案：

倒序删除：从后往前删，不会漏删或越界。

迭代器：用迭代器的remove，边遍历边删，迭代器内部维护了expectedModCount，不会抛异常。

removeIf：jdk8之后新增了removeIf方法，底层就是迭代器遍历，用Lambda指定删除条件，更简洁。

# 如何实现List和数组的互转？

直接用list.toArray()写上转换类型就行。

数组转List，用Arrays.asList()就行，不过返回的是Arrays内部类ArrayList，不是java.util下的ArrayList。他底层是引用的原数组，所以长度是固定的，但是可以改元素内容；基本数据类型的数组不能直接用Arrays.asList()，会被当成一个对象，只会在外面包一层List，实际上还是原数组在里面；想要可变的List，需要转成List后作为new ArrayList的构造参数。

# List list1 = new ArrayList(8)，List list2 = new ArrayList(3) ，然后list1插入8个元素，list2插入3个元素，list1.addAll(list2)，addAll的过程中list1扩容多少次？最终数组长度是多少？那如果换成List list1 = new ArrayList(8)，List list2 = new ArrayList(50) ，然后list1插入8个元素，list2插入50个元素呢？

list1容量8，list2容量3，addAll总共需要装11个元素。ArrayList扩容是1.5倍，8的1.5倍等于12，12大于11，扩容一次，最终数组长度12。

list1容量8，list2容量50，总共需要58。1.5倍是12，12不够用，addAll会直接按目标容量58来扩，也只扩容一次，最终长度58。

不管什么情况，addAll只扩容一次，1.5倍够用就按1.5倍，不够用就直接按目标容量来，不会反复扩。
